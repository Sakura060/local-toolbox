## 0. 三条铁律（从"导入=注册"推导，全文以此为宪法）

1. **只读原软件**：导入/运行/卸载，绝不写被导入软件目录的任何文件。唯一例外：图标提取是
   "读出来存到工具箱自己的数据目录"，原图标文件不动。
2. **清单无代码**：plugin.json 是纯数据。工具箱永不执行"清单文本里写的东西"，
   只执行"清单指向的、用户机器上本来就有的东西"。
3. **进程隔离**：第三方软件都是独立进程（现状已满足）；"随工具箱退出"用 Windows Job Object
   实现，且默认只对一次性运行类开启（GUI 软件挂在 Job 里可能行为异常，见难点 6）。

## 1. 整体判断：哪些成立、哪些不成立

### 成立（照做）
| 你的想法 | 判断 |
|---|---|
| 导入=注册，不是搬运 | ✅ 完全成立，是本功能的第一宪法。补充：图标副本是唯一允许的"复制"，且产物在工具箱目录 |
| 声明式清单，禁止内嵌代码 | ✅ 成立。精确化：清单文本不含可执行内容，但**允许指向**用户机器上已有的可执行物（exe/脚本）——那东西用户自己双击也能跑，工具箱只是替他双击 |
| 独立进程，工具箱是管理员不是宿主 | ✅ 成立，且现有架构天然满足 |
| 向导式导入 + 试运行 + 全程展示"将执行什么" | ✅ 成立，是小白可用的关键 |
| 清单分享让别人导入 | ✅ 成立，但必须和"重新定位"流程配对（见第 8 节 #8），否则分享来的清单全是"已失效" |

### 不成立 / 要改（按重要度排序）
| 你的想法 | 问题 | 改成 |
|---|---|---|
| "权限最小化：默认只允许访问被声明的目录" | **做不到**。Windows 没有可行的用户态沙箱能限制一个普通 exe 的文件访问（AppContainer 可以但绝大多数软件跑不起来，成本爆炸）。承诺做不到的事会毁掉信任 | 声明=展示不=隔离：清单里的"权限声明"用于**告知用户**（"这个软件将能访问你的整个用户目录"），工具箱自己守住的边界是：工作目录、临时文件位置、绝不提权（除非用户确认） |
| "输出契约：如何把结果回填到工具箱界面" | 对任意第三方 GUI 软件不成立——无法解析别人的界面。硬做就是假功能 | 诚实收缩：GUI=只报"已启动"；命令行=截获 stdout 展示 + 输出目录快捷打开；脚本=全支持 |
| "输入契约：写入临时文件/标准输入" | 对 GUI 软件基本不成立（没人收 stdin） | 按类型收缩：GUI=启动参数带文件路径（可选）；脚本/命令行=全支持；其余=无输入 |
| "避免每次都弹 UAC" | Windows 的提权确认是系统级安全机制，不弹窗=绕过 UAC（计划任务法）是安全反模式，杀软敏感、用户困惑 | 能承诺的是：卡片标注"需要管理员"、每次启动弹一次 UAC、文档解释原因。计划任务法列为远期高级选项（默认不做，未验证稳定性） |
| "自动建议分类和中文说明" | 中文说明离线没法可靠自动生成（无 AI、不联网） | 分类用启发式（路径/开始菜单文件夹/文件名关键词）；说明用模板"（未填写）点此编辑"+示例引导，别假装 AI |
| "健康检查" | 对第三方软件没有统一健康口径 | 分型处理（第 2 节）：exe=路径存在+启动后进程活；商店=AppUserModelID 在册；脚本=解释器在+语法可过；URL/文档=永远可用 |

### 从 dsh 迁移的判断（回应"后者居多"）
**理念层三条全部可迁移，机制层大部分不可迁移。**
- 可迁移：自描述（每个插件一份声明）、注册表驱动（核心不认识具体插件）、可插可拔（删目录即卸载）。
  ToolHub 现有 apps/ tool.json 三级注册表就是同构的，本次加第四层"外部软件"。
- 不可迁移的根本原因：**dsh 插件的消费方是 AI（读 Markdown 指令），ToolHub 插件的消费方是
  Windows（启动 exe）**。由此派生四点不同：dsh 插件天然无害（Markdown 不可执行），我们指向真实
  可执行物（安全模型完全不同）；dsh 插件没有进程/生命周期概念，我们全有；dsh 用 npm 分发，
  我们的用户是小白（分发=导出一个 json 文件）；dsh 的 SKILL.md 是给模型读的"何时用我"，
  我们的 desc 是给人读的"这是干嘛的+搜索关键词"。

## 2. 分型表（每类：导入方式 / 启动方式 / 成功判定 / 已知限制）

| 类型 | 例子 | 导入方式 | 启动方式 | "成功"判定 | 已知限制 |
|---|---|---|---|---|---|
| ① 便携 exe（含快捷方式） | Snipaste、Everything 便携版 | 拖 exe 或 **.lnk**（快捷方式里藏着完整启动信息，是首选入口） | subprocess argv 数组，工作目录=exe 所在目录 | 进程 3 秒仍活+有可见窗口（尽力） | 相对路径依赖→工作目录铁律；杀软可能拦 |
| ② 已安装桌面程序 | 微信、7-Zip | **从开始菜单快捷方式导入**（自动解析）；注册表卸载列表做备选 | 解析 .lnk 得到 target+args+workdir | 同① | 安装目录藏在 Program Files，手动找很痛苦→靠 .lnk 解决 |
| ③ 脚本 | .bat/.py/.ps1 | 拖脚本文件 | py=本机 Python（无则 ToolHub 自带 runtime）；bat=cmd /c；ps1=powershell -ExecutionPolicy Bypass -File | 退出码 0 + stdout 无异常字样 | 解释器必须在；ps1 有执行策略与 BOM 编码坑；.sh 不支持（Windows 无原生 bash） |
| ④ 商店应用（UWP/MSIX） | 商店版计算器 | 从"开始菜单全部应用"列表挑选（枚举 Get-StartApps） | explorer.exe shell:appsFolder\<AppUserModelID> | 进程出现在列表 | 拿不到传统路径；图标来自系统缓存（未验证全部可提）；部分应用禁止后台启动 |
| ⑤ 安装包/压缩包 | .msi/.zip | **不导入，引导安装**："这是安装包，不是软件本体。要安装它吗？"（msi 调 msiexec，zip 建议用户自己解压后导出解出来的 exe） | 不适用 | — | 绝不代用户解包安装（越权+风险），只做引导 |
| ⑥ 文件夹/文档 | 项目目录、常用文件夹 | 拖进来 | explorer 打开（文件夹）或系统默认程序（文档） | 必成功 | 不是"软件"但用户视角等价（"我要快速到达的东西"），成本低值得收 |
| ⑦ URL 与协议 | 网页、steam://、mailto: | 粘贴链接 | ShellExecute 交给系统默认处理程序 | 必成功（协议存在时） | 自定义协议要在确认页明示"将打开 xx 协议"；不发起任何网络请求（只是唤起系统处理器） |
| ⑧ 命令行工具 | ffmpeg、adb | 拖 exe + **必须填参数模板**才可用 | argv 数组按模板展开 | 退出码 + stdout 截获 | 无参数模板的命令行工具没有"用"的意义；参数模板是阶段 B |
| ⑨ 常驻/需登录服务 | 本地服务、代理 | 暂不建议导入（v1 明确排除） | — | — | 生命周期、开机自启、端口冲突都是新问题域；v1 在向导里识别并提示"暂不支持" |

## 3. 插件清单 schema（v1）

**双文件设计**：`plugin.json`（用户可编辑、可分享的身份+启动+契约）与 `plugin.state.json`
（工具箱维护的运行统计：上次运行/次数/启用状态）。分享只带前者；卸载删两者+图标缓存+日志。

存放：`ToolHub-工具箱门户\data\plugins\<id>\plugin.json`（工具箱自己的数据目录，
不是用户软件目录——铁律 1）。

```jsonc
{
  "manifest_version": 1,              // 格式版本，为将来升级留后路
  "id": "snipaste",                   // ascii slug，唯一（自动生成，可改）
  "kind": "exe",                      // exe|script|store|url|folder|doc
  "name": "Snipaste 截图贴图",
  "desc": "截图后可以贴在屏幕上对照，比系统截图多一步",
  "version": "1.16.2",                // 从 exe 资源读取，仅展示
  "publisher": "Le Liu",              // 从 exe 资源读取，仅展示
  "source": "manual",                 // manual|lnk|startmenu|scan|share
  "imported_at": "2026-10-02T18:00:00",
  "icon": "icon.png",                 // 相对本插件目录；工具箱生成的副本
  "launch": {
    "target": "%USERPROFILE%\\Tools\\Snipaste\\Snipaste.exe",  // 支持环境变量（分享可移植），UI 展示展开后的真实路径
    "workdir": "{target_dir}",        // {target_dir}=target 所在目录；默认必须是它
    "args": [],                       // 字符串数组；占位符 {file}|{folder}|{text}|{arg:名字}
    "env": {},                        // 附加环境变量（少用）
    "elevate": false,                 // true=ShellExecute runas（每次弹 UAC）
    "window": "normal",               // normal|minimized|maximized
    "use_shell": false                // store/url/doc 必须 true（交给系统）
  },
  "input": {
    "accept": "none",                 // none|file|folder|text|file+folder
    "via": "argument"                 // argument（GUI/命令行）；stdin/tempfile（仅脚本）
  },
  "output": {
    "kind": "window",                 // window|stdout|directory
    "dir": ""                         // kind=directory 时的输出目录（可 {arg:}）
  },
  "lifecycle": {
    "mode": "gui",                    // gui|oneshot|resident
    "close_with_hub": false,          // Job Object 实现；oneshot 默认 true
    "success": "alive_3s",            // alive_3s|exitcode|window_enum
    "timeout_sec": 0                  // oneshot 专用，0=不限
  },
  "display": {
    "category": "图像",               // 沿用现有分类体系，可新建
    "tags": ["截图"],
    "aliases": ["snip", "贴图"],      // 搜索别名（Ctrl+K 命中）
    "pinned": false
  },
  "trust": {
    "origin": "self",                 // self|shared（分享来的首次运行加强提示）
    "confirmed_launch": true          // 用户看过"将执行什么"并确认
  }
}
```

**红线校验（导入时强制，不合格拒绝）**：只允许上述字段（未知字段拒绝）；args/target 是纯字符串；
无 script/code/command 之类字段名；kind=exe 时 target 必须展开后指向 .exe/.lnk；
kind=url 只允许 http/https 或已在确认页明示的自定义协议。

## 4. 导入向导（7 步，含界面元素与文案）

全程右侧固定一个"将执行什么"预览卡，随每步更新；顶部有步骤条；每步可"存草稿"/"上一步"。

| 步 | 界面元素 | 用户可见文案（示例） |
|---|---|---|
| 1 选择 | 大拖拽区（"把软件、快捷方式或文件夹拖到这里"）+「浏览文件」+「从开始菜单挑选」 | 把软件拖进来，或点浏览选择。**导入只是记个路标，不会移动或修改你的软件** |
| 2 识别 | 自动判断（约 1 秒），显示识别卡：类型图标+依据 | 我认出来了：这是一个**便携程序**（单个 exe）。/ 这是一个**快捷方式**，指向 D:\Tools\Snipaste\Snipaste.exe |
| 3 确认启动方式 | 预览卡（自动填充，可改）：将运行 / 工作目录 / 参数 / 窗口模式；高级折叠（环境变量、提权） | 启动时，工具箱会替你做这件事：**运行 D:\Tools\Snipaste\Snipaste.exe**（工作目录：D:\Tools\Snipaste）。它和你自己双击图标完全一样，工具箱不会附加任何动作 |
| 4 试运行 | 大按钮「▶ 试运行」+ 结果区 | ✅ 启动成功——程序窗口应该已经出现了。（工具箱无法替你确认软件内部功能正常）/ ❌ 没能启动：找不到文件。**下一步**：用「重新定位」选择它的新位置 |
| 5 填用途 | 一个文本框 + 3 个可点的示例 | 这一步是为了"以后搜得到"：一句话说明它是干嘛的。例：「批量把照片缩小到 1080 宽」 |
| 6 归类与图标 | 分类下拉（可新建）+ 图标预览（自动提取的原图标 / 字母占位 / 上传自定义） | 图标已从原软件提取（只是复制了一份画面，原软件没动） |
| 7 完成 | 成功卡 + 两个按钮：「打开工具箱看看」「立即再试一次」 | 已加入工具箱。它和内置工具一样可以搜索、收藏、启动 |

**草稿**：任何一步点「存草稿」→ 进管理页标"草稿"，随时继续。

## 5. 管理页与"路径失效修复"

**插件管理页**（左侧导航新增「🔌 我的插件」，与内置工具分开）：
- 列表行：图标 | 名称 | 类型徽标 | 状态徽标 | 来源 | 上次运行 | 次数 | 行内操作（启动/编辑/更多）
- 状态五种：🟢 可用 / 🔴 已失效（找不到文件） / 🟡 暂不可用（设备未连接——可移动盘场景） / ⏸ 已停用 / 🛡 需管理员
- 批量：复选 → 顶部浮条「归类到… | 停用 | 导出 | 移除」
- 编辑页=向导 3/5/6 步的复用；"启用/停用"是清单开关，停用后主界面隐藏但清单保留

**路径失效修复**（绝不静默失败）：
1. 每次启动前校验 target 存在；不存在 → 卡片转红，详情页顶部横幅：
   "原软件不见了（可能被移动或卸载）。工具箱没有动过它——你可以告诉它新位置。"
2. 按钮「重新定位」→ 文件选择器（初始目录=旧路径的父目录）→ 选中新位置 →
   指纹比对提示（"名字相同，大小不同——确定是同一个软件吗？"）→ 更新清单 → 转绿。
3. 若用户选"移除"：只删工具箱自己的四样（清单/状态/图标副本/日志），横幅明示
   "你的软件本身不会被删除"。

## 6. 难点逐条方案与取舍

1. **参数与路径安全**：清单 args 是**字符串数组**，启动走 subprocess 的 argv 列表——引号/空格/中文
   由 Windows 参数传递规则统一处理，工具箱永远不拼接命令行字符串。对比：错误做法
   `cmd /c start D:\My Tools\a.exe`（空格处断裂）；正确做法 argv=`["D:\\My Tools\\a.exe"]`。
   占位符 {file} 等替换后的整个值算一个 argv 元素，绝不二次分词。
2. **管理员权限**：elevate=true → ShellExecute "runas"（系统 UAC 弹窗，每次）。UI：卡片标 🛡、
   向导里明示"每次启动 Windows 都会问你一次，这是系统保护，工具箱不能也不该跳过"。
   不做计划任务法（绕过 UAC 是反模式；远期高级选项，未验证）。
3. **GUI 启动成功判定**：三层递进——进程创建成功（即时）→ 3 秒后进程仍活 → 尽力枚举可见主窗口
   （10 秒，未验证所有软件的窗口可枚举性）。文案如实："已启动。工具箱无法替你确认软件内部功能正常"。
4. **编码**：清单文件强制 UTF-8（读时兼容 BOM）；子进程输出解码顺序 UTF-8 严格 → GBK(cp936) →
   replace 兜底（沿用现有 launcher 的 errors=replace 经验）；脚本解释器解析顺序：清单 interpreter 字段
   > PATH 上的 python > ToolHub 自带 runtime；bat 一律 `cmd /c` 且提醒用户 bat 中文正文的 D13 老坑。
5. **图标**：SHGetFileInfo/PrivateExtractIcons（ctypes，零新依赖，未验证个别加密壳 exe）提取
   256/48/32/16 → 存 PNG 副本到插件目录 → 归一化：64px 画布、统一 4px 内边距、圆角，取不到就用
   首字母+分类色的字母占位（现有体系一致）。绝不写回原文件。
6. **生命周期**：Job Object（JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE）实现"随工具箱退出"。
   取舍：oneshot 默认挂 Job（防孤儿进程）；gui 默认不挂（部分 GUI 在 Job 里行为异常，未验证具体
   名单），用户可在清单里手动打开。
7. **去重**：指纹 = 展开环境变量+小写+去尾点后的 target 绝对路径（store 用 AUMID，url 用整串）。
   同指纹再导入 → "这个软件已经在工具箱里了"，提供"更新路径/换图标/放弃"。不同路径同名 →
   提示疑似升级/搬家，引导"重新定位"而不是生成重复项。
8. **杀软拦截**：检测能力有限（未验证可靠性）：启动失败错误码 5（拒绝访问）/126/1275 等特征 +
   失败时人话分支"可能被安全软件拦下"，指引：查日志 → 加白名单该软件目录 → 重试。绝不自动改杀软设置。
9. **一键整套**：目录扫描 → exe 候选（黑名单：unins*/setup*/update*/crash*/helper*/_gb* 等 + 可选
   大小过滤 + 仅顶层或一层深）→ 勾选列表 → 静默走识别+图标 → 批量草稿 → 用户统一补说明（可跳过）。
   另有"从开始菜单挑选"：枚举 ProgramData+AppData 两处开始菜单 .lnk，按文件夹分组展示。

## 7. 分阶段计划

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| **A（MVP，先做）** | **exe + .lnk**（同一实现路径，拖快捷方式比拖 exe 更常见，必须一起做）+ folder/url/doc 三类"顺手类型"（ShellExecute 一行事）；手动浏览+拖拽导入；完整 7 步向导（含试运行）；图标提取+归一化；去重指纹；管理页（列表/编辑/停用/移除/**失效标记+重新定位**）；plugin.json v1 | 拖一个带空格中文路径的绿色 exe → 向导 → 试运行 → 出现在工具箱可启动；删掉原文件 → 变"已失效" → 重新定位恢复 |
| B | 脚本三类（bat/py/ps1）+ 命令行参数模板 + 输入契约（从工具箱发文件/文本）+ stdout 截获展示 + 批量目录扫描 + 开始菜单导入 | ffmpeg 模板示例全流程可用；扫描"绿色软件"目录批量导入 ≥5 个 |
| C | 商店应用（Get-StartApps 枚举，未验证项多）+ 清单分享/导入（含重新定位配对流）+ 运行统计完善 + 可选 Send To 集成 | A 导出的清单在另一台机器导入后走"重新定位"复活 |

**对"从绿色便携 exe 开始"的评估：方向正确，但要加两个修正。**
① .lnk 快捷方式必须和 exe 同批做——拖拽入口天然会收到 .lnk，且它是"已安装软件"的唯一切实入口
（不做它，分型表第②类在 MVP 里就是空头支票）；② folder/url/doc 虽然不是"软件"，但实现是一行
ShellExecute，放进 MVP 能让向导的识别分支一开始就被真实锻炼。命令行工具（参数模板）不进 MVP：
它是唯一需要新 UI（参数表单）的类型，放阶段 B。

## 8. 你的原始想法遗漏了什么（最重要的一节）

1. **快捷方式（.lnk）才是 Windows 的万能容器**——你把它列为入口之一，但它其实是整个功能的支点：
   .lnk 里存着目标路径+参数+工作目录+图标，"从开始菜单导入已安装软件"全靠解析它。没有它，
   第②类软件用户根本找不到主程序在哪。
2. **manifest 和运行状态要分两个文件**——可分享的清单（plugin.json）和工具箱维护的统计
   （上次运行/次数/启用）混在一个文件里，分享时会把你的私有运行记录一起发出去。
3. **路径环境变量是清单可分享的前提**——`%USERPROFILE%` 写进 target，别人的机器才有匹配机会；
   同时 UI 必须展示展开后的真实路径（否则用户看不到"它到底会运行什么"，违反你的透明原则）。
4. **"暂不可用"和"已失效"是两种状态**——软件在 U 盘上（设备没插）≠ 软件被卸载了。
   混为一谈会让用户误删还能救回来的插件。
5. **输入契约的真正变现是"从工具箱发送"**——不是启动时带参数。右键一条剪贴板记录/一个文件 →
   "用 XX 打开"，这才是插件生态的日常用法；只做启动带参，输入契约就浪费了。
6. **输出回填要诚实降级**（正文第 1 节详述）——不然会做出一个"看起来能收集结果、实际永远空着"的假功能。
7. **权限声明做不到隔离**（正文第 1 节详述）——这是你的方案里最危险的一条承诺，必须改成"告知"。
8. **分享清单必须配"重新定位"**——清单里的 D:\Tools 路径在别人机器上大概率不存在；
   分享机制的价值在"清单结构+说明+参数模板"（尤其命令行模板），路径本身只是占位。
9. **批量扫描的噪声过滤**——绿色软件目录里遍地 unins000.exe/setup/crash handler，
   见 exe 就收会产出垃圾列表；黑名单是必需品。
10. **插件与内置工具要分型展示**——第三方插件没有联邦搜索 API、没有健康接口、详情页没有
    "待办徽标"。必须如实做"两套详情页"，否则到处是点了没反应的死入口。
11. **工作目录默认值是隐形杀手**——绿色软件双击能用、从工具箱启动就报错，九成是工作目录错了。
    "默认=exe 所在目录"要写成铁律并在预览卡里展示出来。
12. **重名冲突**——导入名和内置工具撞名（比如用户也装了个"笔记"）会让搜索和界面混乱；
    需要冲突检测和强制改名。
13. **卸载语义要明示**——"移除插件"删的是工具箱自己的四样（清单/状态/图标副本/日志），
    界面上要说"你的软件不会被删除"，否则用户不敢点。
14. **一次性运行的超时与孤儿**——命令行工具卡死怎么办（timeout 字段）+ 工具箱退出后脚本还在跑
    （Job Object）。GUI 类反而要默认不挂 Job（兼容性），这个"默认值不对称"你不会想到。
15. **启动即最小化**——小工具常见诉求（SW_MINIMIZE），成本一行，体验加分明显。
16. **版本资源重校验**——exe 的 FileVersion 变了 = 原软件更新过 → 提示"重新校验"，
    这是"原软件更新后如何重新校验"的落地答案（读 VS_VERSION_INFO，零依赖）。
