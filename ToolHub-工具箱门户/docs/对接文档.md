# ToolHub 对接文档（给 AI / 程序的机器可读接口说明）

> 版本基准：桌面版 **v0.3.0**（2026-10-25 深夜。插件 A+B+C 全部交付：六类可导入+分享+商店应用；新增工作场景组合）。
> 本文自包含，可直接转交。全部接口经代码实勘（desktop/server.py、desktop/plugins.py、desktop/scenes.py、desktop/cfg.py），
> 无推测内容。约定：**仓库根**=包含 `ToolHub-工具箱门户/`、`localcore/` 等工具目录的父目录（源码运行时即工作区根）。

## 0. 一句话与安全模型

ToolHub 是纯本机的 Windows 工具箱：一个窗口管理 10 个内置本地工具 + 任意用户登记的"外部插件"。

对接方必须知道的三条：

1. **全部 HTTP 服务只绑定 127.0.0.1，无鉴权、无 CORS 头、无 TLS**。它不是公网服务，绝不要暴露到非回环地址。
2. **产品铁律（不可协商）**：插件"导入=登记路标"，绝不复制/移动/修改用户软件；`plugin.json` 清单是纯数据（严格字段白名单，未知字段拒绝导入）；所有数据只落本机，无遥测。
3. **鉴权替代方案**：API 无 token，靠"只有本机进程能连 127.0.0.1"这一边界。对接进程与 ToolHub 需同机。

## 2. 桌面版 HTTP API 完整清单（8650）

约定：请求/响应均为 UTF-8 JSON；错误形如 `{"error": "人话中文"}` + 恰当 HTTP 状态码（400/404/403/502）；POST 请求体上限 64KB。

### 2.1 注册表与状态

| 方法+路径 | 说明 | 请求 | 响应要点 |
|---|---|---|---|
| `GET /` | 单页前端（desktop/page.html） | — | HTML |
| `GET /api/tools` | 合并注册表（内置+apps+插件，四层） | — | `{tools:[tool_view...], categories:[...], warnings:[...], app:{version,...}}`；插件条目含 `kind:"plugin"`、`icon_url`、`needs_admin`、`aliases` |
| `GET /api/status` | 并行探测全部条目 | — | `{status:[{id, online, ms, note?, plugin_state?, plugin_label?, running?}]}`；内置看 online，插件看 running |
| `GET /api/federated?q=<词>&limit=12` | 跨工具搜索（扇出到各在线工具的搜索 API） | query | `{q, groups:[{id,name,ok,count,items:[{title,snippet,url?,detail_url?,when?...}]}]}` |
| `GET /api/recent?per=5` | 各搜索源最新条目 | query | 同上结构 |
| `GET /api/envcheck` | 环境自检 | — | `{envcheck:{verdict,n_fail,n_warn,checks:[{tool?,title,detail,level,fix?}]}}` |

### 2.2 内置工具生命周期

| 方法+路径 | 请求体 | 说明 |
|---|---|---|
| `POST /api/launch` | `{id, params?: {名:值}}` | 无窗口拉起内置工具（params 白名单取自 tool_view.launch_params）；插件 id 走插件启动分支（见 2.4） |
| `POST /api/stop` | `{id}` | 内置工具：按端口 netstat 反查 PID + taskkill 树杀；插件：杀 PluginRunner 记录的进程 |
| `GET /api/log/<工具id>?lines=200` | — | 桌面版拉起的内置工具实例日志尾部（lines 钳制 10-1000） |
| `GET /proxy/<工具id>/<路径>` | — | 只读透传到该工具端口（段边界白名单 + 拒 `..` + 只 GET + 8MB 截断，超限响应头 `X-ToolHub-Truncated: 1`） |

### 2.3 设置

| 方法+路径 | 说明 |
|---|---|
| `GET /api/settings` | `{settings:{favorites:[id...], order:[id...], first_run_done, theme}}` |
| `POST /api/settings` | 同名字段 patch（id 会对照当前注册表白名单过滤）；`{"reset": true}` 清空 |

### 2.4 外部插件（万物皆插件 A+B）——对接主战场

**枚举与详情**

| 方法+路径 | 说明 |
|---|---|
| `GET /api/plugins` | `{plugins:[{id,kind,name,desc,category,state,running,source,imported_at,last_launched,run_count,icon_url,target,needs_inputs}]}`。`state` ∈ ok/invalid/disabled/draft；**`needs_inputs:{file,folder,text,args:[参数名]}` 是参数模板声明**，渲染启动表单用 |
| `GET /api/plugins/<id>` | `{manifest:{...plugin.json 原文...}, state:{...plugin.state.json...}}` |
| `GET /api/plugins/<id>/icon` | 64px PNG（无图标 404） |
| `GET /api/plugins/<id>/log` | `{id, alive, log}`（log 为尾部 8KB 文本，含每次启动参数与 stdout） |
| `GET /api/plugins/startmenu` | 阶段 B：`{ok, items:[{path,name,group}]}`（两处 Start Menu 的 .lnk，已去重分组） |
| `GET /api/plugins/storeapps` | 阶段 C 二期：`{ok, items:[{aumid,name}]}`（Get-StartApps 枚举的 UWP/MSIX，AppID 含 `!`） |

**导入与运行**

| 方法+路径 | 请求体 | 行为 |
|---|---|---|
| `POST /api/plugins/probe` | `{path, name_hint?}` | 识别一个路径/URL/AUMID → `{ok, manifest, errors, fingerprint, duplicate?, icon_tmp, kind_label}`。支持 exe/.lnk/folder/url/doc/脚本(.py/.pyw/.bat/.cmd/.ps1；.sh 拒绝)/**商店应用**（`path="shell:appsfolder\\<AUMID>"` + name_hint=显示名）。**不落盘** |
| `POST /api/plugins/commit` | `{manifest, draft?, confirmed_launch?, icon_tmp?, allow_duplicate?}` | 校验→写 `data/plugins/<id>/plugin.json`(+state)。id 撞内置工具拒绝；同指纹重复返回 `{duplicate:{id,name}}` 除非 allow_duplicate。draft=true 存草稿不进主界面 |
| `POST /api/plugins/test` | `{manifest, inputs?}` | 试运行（不落盘，直接按清单执行一次） |
| `POST /api/plugins/scan` | `{path, depth?=1}` | 阶段 B：批量扫描目录找 exe/.lnk → `{ok, items:[{path,name,size,mtime,blocked}], scanned}`。`blocked=true` 是黑名单命中（卸载器/安装器等），默认不勾 |
| `POST /api/plugins/export` | `{ids: [插件id...]}` | 阶段 C：导出可分享清单 → `{ok, text}`（text 为 JSON 文本，格式见下）。**绝不包含运行状态/日志/图标** |
| `POST /api/plugins/import-preview` | `{text}` | 导入前预检（不落盘）→ `{ok, items:[{manifest, errors[], exists, conflict?}]}`。conflict.type ∈ duplicate(不同ID同指纹)/id_taken(同ID已占用)/builtin(与内置工具撞名)；`exists=false` 表示目标路径本机不存在（可导入，导入后为 invalid 状态走"重新定位"） |
| `POST /api/plugins/import` | `{items: [manifest...], rename?: {旧id:新id}}` | 确认导入。逐条完整再校验（不因经过预检而豁免），部分成功语义；与内置撞名的条目在服务端过滤。返回 `{ok, results:[{ok,id?,error?}]}`。导入的插件 `trust.origin="shared"` |
| `POST /api/launch`（id=插件） | `{id, inputs?}` | 启动插件。**`inputs:{file,folder,text,args:{名:值}}` 填参数模板占位符**；响应 `{ok, pid?, hint, already?, output_dir?}`（output.kind=directory 时给展开后的输出目录） |
| `POST /api/open-dir` | `{dir}` | 用资源管理器打开一个**真实存在**的目录（只收目录，防注入）；不存在 → `{ok:false,error}` |

**管理**（路径前缀 `/api/plugins/p/<id>/`，全部 POST）

| 子路径 | 请求体 | 行为 |
|---|---|---|
| `launch` | `{inputs?}` | 同 /api/launch 插件分支 |
| `stop` | `{}` | taskkill 该插件进程树 |
| `relocate` | `{path}` | 软件搬家后重指路标；exe 类必须选 .exe，workdir 自动跟随 |
| `edit` | `{name?,desc?,category?,tags?,args?,elevate?,window?}` | 改清单元数据（全部有长度钳制） |
| `disable` / `enable` | `{}` | 停用（移出主界面）/启用 |
| `remove` | `{}` | 删工具箱自己的清单/状态/图标/日志四样，**绝不碰用户软件本体** |

### 2.5 工作场景（v0.3 新增）

场景 = 一组引用的清单（工具 id / 文件夹 / 文件 / 网址），存 `data/scenes.json`：
`{"format":"toolhub-scenes","version":1,"scenes":[{id,name,icon,items:[{kind,ref}],created_at,last_launched}]}`
（item.kind ∈ tool/folder/file/url；tool.ref = 注册表 id，内置与插件统一；白名单校验；原子写；损坏自动备份恢复）。

| 方法+路径 | 请求 | 说明 |
|---|---|---|
| `GET /api/scenes` | — | `{scenes:[...]}` |
| `GET /api/scenes/p/preview?id=` | — | 逐项预检（不执行）：`{items:[{index,kind,ref,label,status,reason}]}`，status ∈ ok / skip_running（已运行，启动时跳过）/ invalid（引用失效+原因） |
| `POST /api/scenes/save` | `{scene}` | 新建/更新（id 撞他人拒绝；未知字段/超限拒绝；空 items 允许） |
| `POST /api/scenes/p/<id>/launch` | `{}` | 顺序启动，单项失败继续 → `{ok, session, results:[{index,kind,ref,status,detail}], untracked}`。**session 只含"本会话启动且可识别"的停止句柄**；已运行项跳过且不可停 |
| `POST /api/scenes/stop` | `{session}` | 只停 session 记录的项（内置=端口杀：启动前离线保证是我们的实例；插件=进程句柄）→ `{ok, stopped[], skipped[]}`。文件夹/文件/网址 untracked，**绝不提供停止**（防误杀） |
| `POST /api/scenes/p/<id>/duplicate` | `{}` | 复制场景（id 加 -copy） |
| `POST /api/scenes/p/<id>/remove` | `{}` | 删除场景（只删清单） |

## 3. plugin.json 完整 Schema（manifest_version: 1）



严格白名单校验（desktop/plugins.py `validate_manifest`），**任何未知字段直接拒绝**。对接方生成清单时只能用以下字段：

```
顶层:  manifest_version(必须=1) id(^[a-z0-9][a-z0-9-]{1,39}$) kind name(1-60字)
       desc(≤300字) version publisher source(manual|lnk|startmenu|scan|share)
       imported_at icon(相对插件目录文件名,约定"icon.png")
launch: target(必须) workdir args(字符串数组) env(对象) elevate(bool)
       window(normal|minimized|maximized|hidden) use_shell(bool)
       interpreter(python|cmd|powershell,仅 kind=script) aumid(仅 store)
input:  accept(none|file|folder|file+folder) via(argument|stdin|tempfile)
output: kind(window|stdout|directory) dir(output.kind=directory 时,可含占位符)
lifecycle: mode(gui|oneshot|resident) close_with_hub(bool) success(alive_3s|exitcode|window_enum)
       timeout_sec(int,>0 时超时 taskkill 强杀)
display: category tags[] aliases[](搜索命中用) pinned
trust:  origin(self|shared) confirmed_launch resolved_from
```

- `kind` 合法值：`exe / script / store / url / folder / doc`。**当前开放创建的是 exe/script/url/folder/doc（store 属阶段 C，probe 会拒绝）**。
- `kind=exe` 的 target 展开环境变量后必须指向 `.exe`/`.lnk`；`kind=url` 必须带协议头。
- 双文件设计：`plugin.json`（可分享）与 `plugin.state.json`（工具箱维护：draft/enabled/run_count/last_launched/last_exit/last_ok）同目录。分享/迁移只带前者。
- **分享文件格式**（`/api/plugins/export` 的 text）：
  ```json
  {"format": "toolhub-plugin-share", "version": 1,
   "exported_at": "2026-10-25T...", "plugins": [ {plugin.json 清单原文...} ]}
  ```
  规则：version ≠ 1 拒整文件；每条插件导入时走与手动导入**完全相同**的白名单校验（未知字段/超长/缺字段均拒绝，不因来源是导出而豁免）；icon 恒为空（图标导入方按目标存在与否重新提取或字母占底）；目标路径不存在不阻止导入——插件以 invalid 状态进入，用既有 relocate 闭环恢复。

## 4. 参数模板占位符（阶段 B 核心机制）

`launch.args[]` 与 `output.dir` 里可写以下占位符，启动时由 `inputs` 提供值展开：

| 占位符 | 含义 | inputs 来源 |
|---|---|---|
| `{file}` | 一个文件完整路径 | `inputs.file` |
| `{folder}` | 一个目录完整路径 | `inputs.folder` |
| `{text}` | 一段文本 | `inputs.text` |
| `{arg:任意名}` | 命名参数 | `inputs.args[名]` |
| `{file_dir}` / `{file_stem}` | {file} 的父目录 / 主文件名（派生） | 依赖 `inputs.file` |
| `{target_dir}` | 仅 workdir 可用：target 所在目录 | 自动 |

规则（铁律级）：

1. **替换后的整值仍是单个 argv 元素，绝不二次分词**——空格/引号/中文路径安全（实现用 str.replace 而非 re.sub，因为 Windows 路径反斜杠会被 re.sub 替换串误当转义）。
2. 用了占位符但启动时缺对应输入 → 人话报错（HTTP 200 + `ok:false, error:"参数里用了 {file}，但启动面板里没有选择文件…"`），**不是静默空串**。
3. `input.accept` 只是"向用户声明会要什么"的告知字段，不是沙箱限制（Windows 用户态无法限制 exe 的文件访问，产品承诺里明确不假装隔离）。
4. 脚本类（kind=script）默认 `lifecycle={mode:oneshot, close_with_hub:true, success:exitcode}`、`window=hidden`、`output.kind=stdout`；解释器解析顺序：清单 `interpreter` > PATH python > 工具箱自带 runtime（`workspace/../runtime/python.exe`）。bat→`cmd /c`；ps1→`powershell -NoProfile -ExecutionPolicy Bypass -File`。

## 5. 对接方如何"加一个工具/插件"

三条路，按集成深度递增：

1. **登记现成软件**（零代码）：`POST /api/plugins/probe` + `POST /api/plugins/commit`，或直接在 `data/plugins/<id>/` 放一对 plugin.json/plugin.state.json（要过白名单校验，enabled 且非 draft 才进主界面）。批量：`POST /api/plugins/scan` 逐个 commit。
2. **apps/ 目录**（零代码接入自研工具）：仓库根的 `apps/\<你的工具\>\tool.json` + 同目录可运行程序。字段见 `apps\番茄钟\tool.json`（id/name/icon/category/desc/port/launch.argv（含 `{python}` 占位）/proxy_prefixes/about）。桌面版启动时自动扫描，无需注册。
3. **深度集成**（参与联邦搜索/徽标）：toolhub 层的 federated.py 适配器 + registry 注册（参考各内置工具实现），或直接改 desktop/cfg.py BUILTINS。改动后跑 `python -m unittest discover -s tests`（167 个）。

## 8. 最小对接示例（curl 风格伪码）

```
# 列出全部插件（含参数模板声明）
GET http://127.0.0.1:8650/api/plugins

# 登记一个 ffmpeg 压缩命令（参数模板）
POST /api/plugins/probe        {"path": "D:\\Tools\\ffmpeg\\bin\\ffmpeg.exe"}
POST /api/plugins/commit       {"manifest": { ...probe 返回的 manifest,
    "launch": {"target": "D:\\Tools\\ffmpeg\\bin\\ffmpeg.exe", "workdir": "{target_dir}",
               "args": ["-i", "{file}", "-vcodec", "libx264", "-crf", "28",
                        "{file_dir}\\{file_stem}_压缩.mp4"], "use_shell": false},
    "input": {"accept": "file", "via": "argument"},
    "lifecycle": {"mode": "oneshot", "close_with_hub": true, "success": "exitcode", "timeout_sec": 3600}},
    "confirmed_launch": true}

# 带输入启动（每次换文件）
POST /api/launch               {"id": "<上面返回的 id>", "inputs": {"file": "D:\\视频\\a b.mp4"}}
→ {"ok": true, "pid": 1234, "output_dir": "D:\\视频", ...}

# 看运行输出/退出码
GET /api/plugins/<id>/log      → log 含 stdout 与 "----- 进程退出（代码 0）-----"
```
